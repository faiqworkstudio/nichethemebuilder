# Demo Roadmap

## Portfolio strategy
Build complete, convincing demos one at a time. Prefer quality and distinction over many unfinished homepages. First three demos should demonstrate three different business problems and three materially different design directions.

## Status definitions
- `BACKLOG` — planned, not started.
- `NOT STARTED` — prioritised but not yet begun.
- `IN PROGRESS` — active implementation.
- `REVIEW` — feature-complete; quality checks remain.
- `COMPLETE` — quality gates in `CLAUDE.md` passed.
- `PAUSED` — intentionally paused with reason documented.
- `RETIRED` — removed from active portfolio, with reason recorded.

## Milestones
### M0 — Repository and tracking setup
- [ ] Inspect repository and current framework.
- [ ] Establish project scripts and baseline checks.
- [ ] Create session log, design decisions and known issues.
- [ ] Identify how demos are routed and previewed.

### M1 — Demo 01: Interior design / renovation
- [ ] Write art-direction brief.
- [ ] Reserve theme in tracker.
- [ ] Build complete Thai-English site.
- [ ] Implement functional enquiry form or explicit demo mode.
- [ ] Test responsive layouts, links, language switcher and SEO.
- [ ] Run checks and review actual rendered page.
- [ ] Mark complete only when quality gates pass.

### M2 — Demo 02: Beauty / aesthetic clinic
- [ ] Use a materially different primary theme and layout.
- [ ] Avoid fabricated credentials, outcomes and testimonials.
- [ ] Implement Thai-English site and clear enquiry path.
- [ ] Run quality gates.

### M3 — Demo 03: Boutique hotel / serviced apartment
- [ ] Use a third distinct primary theme and layout.
- [ ] Integrate a real configured booking destination or clearly labelled demo state.
- [ ] Run quality gates.

### M4 — Expansion
Continue through the theme tracker. Prioritise based on prospect feedback and the industries the studio wants to sell to.
