# Design Decisions

Append durable decisions with date, rationale and status. Do not silently reverse a decision; document the reason.

## Active decisions
1. **Human-first design.** Date: 2026-10-18. Prefer natural copy, purposeful whitespace, strong composition, useful interactions and craft over generic AI-looking decoration.
2. **Studio reference.** Date: 2026-10-18. Reuse the earlier OXE Marketing quality bar: premium, human, modern, trustworthy, creative, professional; Apple-like clarity; restrained soft depth; navy/blue/light palette where appropriate. Do not force this palette on every client demo.
3. **Studio naming.** Date: 2026-10-18. User requests the portfolio be for “Klickdoe”; previous work references OXE Marketing. Keep the label configurable and inspect the repo for current brand assets before making changes.
4. **Distinct themes.** Date: 2026-10-18. Every demo gets a tracked theme and a unique layout grammar; recoloring one template does not count as a new design.
5. **Honest demo content.** Date: 2026-10-18. Never present invented client work, testimonials, credentials, booking results or performance numbers as real.
6. **Bilingual quality.** Date: 2026-10-18. Thai and English need real localized content, language metadata, forms, navigation and typography checks.
7. **Stack: Next.js 16 App Router + TypeScript + CSS Modules.** Date: 2026-10-18. Status: active. The repo was empty. Static generation suits sales demos (fast, cheap to host), `next/image` and `next/font` cover image optimisation and Thai font loading, and CSS Modules keep each demo's styles isolated without a CSS framework imposing a shared look.
8. **One folder per demo, own root layout.** Date: 2026-10-18. Status: active. Each demo lives in `src/demos/<slug>/` with its own config, content, components, assets and theme, plus a thin route folder with its own root layout (fonts, `lang`, metadata). Demos never import each other. This keeps the GitHub repo easy to navigate and lets a demo be lifted out for a client.
9. **Locale in the URL, Thai default for Bangkok demos.** Date: 2026-10-18. Status: active. `/th` and `/en` are separate static pages with hreflang alternates and a correct `<html lang>`; `/demos/<slug>` redirects to `/th`. The switcher keeps the section anchor.
10. **Demo pages are `noindex`.** Date: 2026-10-18. Status: active. Fictional businesses should not compete in search results with real firms; the Klickdoe showcase stays indexable.
11. **Forms: honest preview mode by default.** Date: 2026-10-18. Status: active. Without a configured endpoint the form validates, then shows "Preview only — nothing was sent" with a summary and copy button. Setting `NEXT_PUBLIC_<DEMO>_ENQUIRY_ENDPOINT` switches it to a real POST with sending / sent / failed states.
12. **Showcase screenshots are generated, not hand-made.** Date: 2026-10-18. Status: active. `npm run screenshots` captures each demo at 1440, 820 (iPad) and 390 px from the running build, discovering demos via `src/demos/*/showcase.ts`, so screenshots always match the real site.
13. **Contact details stay null until real.** Date: 2026-10-18. Status: active. No invented phone numbers, LINE IDs or addresses; UI shows "not connected in this demo" or hides the block.
14. **Showcase redesigned as a "studio wall".** Date: 2026-10-18. Status: active (supersedes the first, more SaaS-like shell). The user asked for a more creative, human feel: warm paper, taped screenshot prints, Caveat handwriting used sparingly for notes, a "try this" sticky note per demo, sector filter, and an annotated real phone screenshot. Navy/blue from the studio DNA is kept for type and actions.
15. **Shared low-level primitives, never shared compositions.** Date: 2026-10-18. Status: active. `src/components/LocaleSwitch`, `src/lib/contact` (Thai phone / LINE / email), `src/lib/format` (฿), `src/lib/seo` (bilingual metadata) are reused by every demo. Section components, CSS and content stay inside each demo folder.
16. **Pure logic beside each demo, unit tested.** Date: 2026-10-18. Status: active. Each demo's form/booking rules live in a React-free module (`enquiry.ts`, `consult.ts`, `booking.ts`) that must not import images, so `tests/*.test.ts` can run them in Node.
17. **One smoke script per demo.** Date: 2026-10-18. Status: active. `scripts/smoke-<slug>.mjs`; `npm run smoke` runs them all against a running build.
